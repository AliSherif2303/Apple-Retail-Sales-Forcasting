- Aggregates data at the city/country level using `prepare_geographic_data()`
- Computes key derived metrics: `revenue_per_store`, `units_per_transaction`, `market_maturity`
- Implements a `GeographicMarketClustering` class with:
  - **K-Means clustering**
  - **Gaussian Mixture Model (GMM)** soft clustering

  - **Elbow method** & **Silhouette analysis** for optimal `k`
  - Cluster profiling with automatic market-type labeling

#### Output:
- 47 cities across 19 countries analyzed
- Optimal clusters: **2** (according to silhouette score)
- 5 clusters used (hardcoded `n_clusters=5`)

#### Issues Identified:

> [!WARNING]
> **Issue 1: Mismatch between optimal `k` and actual `k`**
> The silhouette analysis determines the optimal number of clusters is **2**, but the model uses **5 clusters** (hardcoded). This contradicts the model's own optimization findings.

> [!WARNING]
> **Issue 2: Hardcoded file path**
> The data is loaded from `/content/merged_city_sales_data.csv`, which is a Google Colab-specific path. This makes the notebook non-portable.

> [!NOTE]
> **Issue 3: SettingWithCopyWarning risk**
> The `fit_clusters()` method modifies `city_data` in-place (e.g., `city_data['kmeans_cluster'] = ...`), which may trigger `SettingWithCopyWarning` if `city_data` is a slice of another DataFrame. Use `.copy()` or `.loc[]` assignment to be safe.

> [!NOTE]
> **Issue 4: Deterministic cluster labels**
> The `profile_clusters()` method uses simple rule-based logic (if store_count > 5, "Premium"; elif > 3, "Growth"; etc.) for labeling clusters. These thresholds are arbitrary and may not generalize well to different datasets.

#### Recommendations:
1. **Re-run clustering** with `n_clusters=2` (the optimal value) or provide justification for using 5 clusters
2. **Parameterize the data path** — use a config file or relative path
3. **Add `.copy()`** when modifying DataFrames in-place
4. **Consider using DBSCAN** or **HDBSCAN** for density-based clustering, which doesn't require specifying `k` upfront

### 2.3 Section 3: Hierarchical Bayesian Market Model (PyMC)

#### What it does:
- Implements a `HierarchicalMarketModel` class using **PyMC (v5)**
- Models revenue as a function of GDP per capita and internet usage percentage
- Uses hierarchical priors:
  - `mu_alpha` (global intercept hyperprior)
  - `mu_beta` (global coefficient hyperpriors for GDP & internet)
  - Country-specific `alpha` and `beta_gdp`, `beta_internet`
  - Log-normal likelihood with `sigma`
- MCMC sampling with NUTS: 2000 draws, 1000 tune, `target_accept=0.99`
- Predicts revenue for new markets
- Visualizes country-level effects

#### Output:
- MCMC sampling completed but with **17 divergences** after tuning
- **Effective sample size per chain < 100** for some parameters
- Posterior plots generated for global intercept, GDP coefficient, and internet usage coefficient

#### Issues Identified:

> [!CAUTION]
> **CRITICAL Issue: Runtime Error in `predict_new_market()`**
> ```
> AttributeError: 'tuple' object has no attribute 'values'
> ```
> **Location:** Line 82 of the cell — `self.model.coords["country"].values`
> **Root Cause:** In PyMC v5, `model.coords` returns a dictionary of tuples (not arrays with `.values` attribute). The code incorrectly assumes coords have a `.values` property.
> **Fix:**
> ```python
> # Replace:
> if country_name and country_name in self.model.coords["country"].values:
>     country_idx_pred = list(self.model.coords["country"].values).index(country_name)
> 
> # With:
> if country_name and country_name in self.model.coords["country"]:
>     country_idx_pred = list(self.model.coords["country"]).index(country_name)
> ```

> [!WARNING]
> **Issue: MCMC Divergences**
> 17 divergences were detected after tuning. This indicates the sampler encountered regions of the posterior that are difficult to explore efficiently.
> **Recommendations:**
> - Increase `target_accept` further (e.g., 0.995 or 0.999)
> - Consider **reparameterizing** the model (e.g., using non-centered parameterization for hierarchical models)
> - Add more informative priors if domain knowledge is available
> - Try increasing `tune` iterations (e.g., 2000-5000)

> [!WARNING]
> **Issue: Low Effective Sample Size (ESS)**
> The error log states: "The effective sample size per chain is smaller than 100 for some parameters."
> This means the MCMC chains have not converged well, making posterior estimates unreliable.
> **Recommendations:**
> - Increase `draws` (e.g., 5000-10000)
> - Use multiple chains and check convergence diagnostics (`r_hat`)
> - Consider simplifying the model if convergence remains poor with 47 cities

> [!NOTE]
> **Issue: Small dataset for Bayesian hierarchical model**
> With only 47 cities and 19 countries, the hierarchical model may be over-parameterized. Each country has country-specific intercepts and 2 coefficients, creating a large parameter space relative to the data size.

#### Recommendations:
1. **Fix the `predict_new_market()` bug** — replace `.values` with direct tuple access
2. **Address divergences** via reparameterization (non-centered) or stronger priors
3. **Increase draws and chains** for better convergence
4. **Add convergence diagnostics** (e.g., `az.summary()`, `az.plot_trace()`, `r_hat` values)
5. **Consider a simpler model** given the small dataset size (e.g., pooled regression instead of full hierarchical)

### 2.4 Section 4: Transfer Learning for Market Insights

#### What it does:
- Implements a `MarketTransferLearning` class
- Splits markets into "mature" (store_count ≥ 3) and "emerging" (store_count < 3)
- Trains a **Random Forest Regressor** on mature markets to predict `revenue_per_store`
- Features: GDP per capita, internet usage, product variety, avg transaction value, units per transaction, population
- Predicts "revenue uplift potential" for emerging markets
- Visualizes: current vs predicted revenue, uplift percentage, GDP vs internet scatter, store count vs uplift

#### Output:
- 9 mature markets, 38 emerging markets
- Train R²: **0.968**, Test R²: **0.918** (very high, but see caveats)
- Feature importances: GDP per capita (0.243), units_per_transaction (0.220), avg_transaction_value (0.192), population (0.186), internet_usage (0.159), product_variety (0.000)

#### Issues Identified:

> [!WARNING]
> **Issue: Extremely small training set**
> With only **9 mature markets**, an 80/20 split gives ~7 training and ~2 test samples. The R² of 0.918 on 2 test points is statistically meaningless — it's essentially fitting noise.

> [!WARNING]
> **Issue: Overfitting concern**
> A Random Forest with 100 estimators on 7 training samples is almost certainly overfitting. The high train R² (0.968) and test R² (0.918) on such tiny samples should not be trusted.

> [!NOTE]
> **Issue: product_variety has zero importance**
> The feature `product_variety` has importance of exactly 0.000, meaning it contributes nothing to the model. This is because all cities have the same value (89) for this feature. It should be removed.

> [!NOTE]
> **Issue: "Transfer Learning" is a misnomer**
> This is not transfer learning in the machine learning sense. True transfer learning involves pre-training on one domain and fine-tuning on another. This is simply training a model on one subset and predicting on another. A more accurate name would be "Cross-Market Prediction" or "Market Potential Estimation."

#### Recommendations:
1. **Remove `product_variety`** as a feature (constant value across all cities)
2. **Use cross-validation** instead of a single train/test split with such a small dataset
3. **Consider simpler models** (e.g., linear regression, ridge regression) given the tiny dataset
4. **Add confidence intervals** to predictions to communicate uncertainty
5. **Rename the approach** — "Transfer Learning" is misleading here
6. **Add leave-one-out cross-validation** (LOOCV) for better validation with small datasets

- **Use HDBSCAN** — automatically determines the number of clusters, handles noise, and works well with varying cluster densities

- **Add the Gap Statistic** as an additional method for determining optimal `k`

### 4.2 For Market Modeling (Section 3)
Instead of a full hierarchical Bayesian model on 47 data points:
- **Use a simpler Bayesian linear regression** with partial pooling
- **Consider Stan or NumPyro** for better MCMC performance
